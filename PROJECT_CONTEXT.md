# Контекст проекта Discord Bot

## Назначение и стек

Многофункциональный бот для сервера общения и ивентов Discord. Стек: Python 3.11, discord.py 2.x, SQLite через aiosqlite. Целевой хостинг — VPS Ubuntu 22.04/24.04 с systemd; путь развёртывания — `/opt/discord-bot`.

## Архитектурные решения

- Один бот с расширениями-cogs в `modules/`.
- Настройки ID каналов, ролей и категорий хранятся в таблице `settings`; структуру сервера бот создаёт при запуске.
- Проверка стафф-прав выполняется по названиям ролей: `Support | Admin`, `Moderator | Staff`, `Eventer | Master` и т. п.
- Владелец сервера и роль `Owner` защищены от модерационных действий, кроме предусмотренного режима ивента.
- Слеш-команды регистрируются через `app_commands`; логирование направляется в каналы, указанные в `settings`.

## Ветки стаффа

Ветки: Support, Moderator и Eventer. В каждой предусмотрены ранги Admin, Curator, Master и Staff.

## Функциональные решения

- Верификация через `/verify` с панелью в канале верификации и кнопками одобрения/отказа.
- Модерация через `/action`: warn, mute_text, mute_voice, ban, kick и перемещение в голосовой канал. Три активных варна приводят к бану на 30 дней; срок мута ограничен 72 часами. Боты, автор команды, владелец и Owner не должны быть целью наказания, за исключением предусмотренного event mode.
- Голосовое время учитывается в голосовых категориях веток, без AFK. Для стаффа планируются недельные отчёты о выполнении ПТ.
- Anti-Nuke использует whitelist и пороги частых разрушительных действий; защищённые каналы требуют ручного подтверждения.
- Снапшоты структуры сервера создаются автоматически и вручную; хранится до 10 последних.
- `/report` маршрутизирует жалобы по веткам, баг-репорты направляет в coder-log.
- `/apply` принимает заявки в стафф; для собеседования создаётся временный голосовой канал.
- Профили разделены на пользовательский, стафф и ивент-профиль. Экономика пока частично заглушена.
- ИИ-анализ и создание GitHub issue при ошибках — опциональное/планируемое расширение; ключи интеграций должны задаваться через окружение, не коммититься.

## Хранение данных

Основные таблицы SQLite: `users`, `staff_branches`, `punishments`, `voice_sessions`, `quotas`, `currency`, `join_history`, `settings`, `antinuke_whitelist`, `protected_channels`, `event_mode`, `reports`, `applications`, `active_branch`, `antinuke_events`. Файл базы данных и резервные копии исключены из Git.

## Секреты и конфигурация

Реальные токены и ключи не добавлять в репозиторий. Использовать `.env` на сервере и `.env.example` как шаблон. Сервисные ключи Google Sheets хранить отдельно от репозитория.
